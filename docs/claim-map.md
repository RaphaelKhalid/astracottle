# What would make a public-state proxy useful?

The target is evidence that supports oversight of consequential actions. A visible record does not earn trust merely by being detailed, consistent with the answer, or required by a schema.

| Claim | Evidence needed | What would weaken it |
| --- | --- | --- |
| The application enforces the state boundary | Saved input packets, record commitment before action, fresh calls and no unintended state transfer | The action also receives a previous answer, decisive source facts, or unlogged context |
| The record preserves decision-relevant evidence | Source comparison and successful later requests, including requests unknown when the record was written | Missing or misstated facts, unsupported provenance, or usefulness confined to a precomputed answer |
| The action depends appropriately on the record | Prespecified relevant fact changes affect decisions; irrelevant changes preserve them; missing facts trigger suitable uncertainty | The action ignores decisive changes or follows unsupported assertions |
| The record improves review | Independent reviews of the same candidate and original evidence with versus without the record; report false flags as well as catches | No measurable gain, more false reassurance, or benefit entirely explained by generic evidence organization |
| The carried record provides distinctive review value | Compare it with an independently generated record of matched schema and capacity that never sees the candidate | An independent aid performs as well or better; actual carriage may then be unnecessary for review assistance |
| The complete system is more dependable | Fewer unflagged violations per assigned task, adequate task completion and reported missing/invalid outcomes on held-out tasks | Apparent detection gains caused by excessive deferral, degraded utility, selected easy failures or unreported cases |

These claims require separate measurements. For example, a faithful copy can preserve evidence but fail to help a reviewer; an inaccurate record can still reveal the origin of an error; a useful summary can help review without describing the actor's internal computation.

For current export and release fixtures, policy is executable and source data structured. Deterministic checks are an essential reference and can be the appropriate operational control. Model-based review should not be presented as necessary when the relevant rule can already be checked directly.

The application boundary is observable at the supplied-input level. It does not inspect server-internal state or establish a complete account of private computation. Any successful result is limited to the tested task distribution, model configuration, record format and monitor conditions.

## Current status after Experiment 006

- Experiment 002 supports appropriate use of supplied public facts in two simple task cases.
- Experiment 003 confirms six safe task completions and exposes solved-answer content inside facts records.
- Experiment 004 preserves all source facts before a hidden request, with 32 safe task completions. The model inventories equal the deterministic inventory, so no distinctive reasoning signal is established.
- Experiment 005 finds perfect flag decisions in every view on eight safe and eight constructed candidates. Carried and independent inventories are identical, so their differences do not identify a carriage effect.
- Experiment 006 finds accurate pre-action forecasts when reviewers see the actual faulty state, but a simple mismatch heuristic is also perfect. Harmless mismatches are the next missing control.
- Experiment 006 supplies actor-generated violations under experimenter-injected state faults. A naturally arising failure population, calibrated trust and a general advantage over deterministic checks remain unestablished.

Each new experiment should update this claim map without replacing negative or inconclusive observations. A bounded development result does not by itself justify a general reliability claim or a deployed trust score.
